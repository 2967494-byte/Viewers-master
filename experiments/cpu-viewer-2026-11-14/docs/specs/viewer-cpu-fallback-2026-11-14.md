# Резервный CPU / Canvas просмотрщик

Дата: 14 ноября 2026. Реализован и проверен локально. В production этой задачей не опубликован.

## Запуск

- До `appInit` выполняется существующая проверка реального WebGL 2 и создания 3D-текстуры.
- Успешная проверка сохраняет обычный OHIF / Cornerstone GPU-путь и его адаптивное ограничение памяти.
- При отказе автоматически загружается отдельный `CpuViewer`, без инициализации GPU-движка и volume viewport. Это не переключатель `setUseCPURendering` для Cornerstone: установленная версия не поддерживает CPU VolumeViewport.
- Для принудительной локальной проверки добавляется `?render=cpu` к ссылке `/3dviewer/v/<token>` либо `/3dviewer/`. Параметр не отменяет проверку доступа к исследованию.
- Это резерв при первоначальной проверке. Автоматический перенос уже открытого GPU-исследования после поздней потери контекста пока не реализован.

## Функции

- Три синхронные MPR-плоскости в физических координатах DICOM; общий крест, прокрутка срезов колесом, поворот согласованных плоскостей шагом 5°.
- Независимый масштаб, перемещение изображения, вписывание и раскрытие окна с сохранением выбранной физической точки.
- Общее окно яркости/контраста; одиночный срез и среднее/MIP для слоя 1–20 мм. Толстый слой доступен после полной загрузки.
- Линейные измерения в миллиметрах; скрытие осей кнопкой и Enter, без остаточной точки.
- Автоматическая панорама на CPU; ручная дуга при неудаче автоматического поиска. Нажатие/перетаскивание по панораме переводит три MPR к соответствующему месту.
- Чтение текущего опубликованного сжатого поколения через тот же CRM resolve и проверку manifest/index, что у основного режима. Локальный выбор файлов/папки DICOM.
- Объёмная 3D-модель, установка имплантов и полный набор инструментов основного GPU-режима в этот резервный интерфейс не входят. Ограничение явно показано над окнами.

## Геометрия и память

- Чёрно-белые CT/MR, 8/16/32 бита; точные IPP/IOP/PixelSpacing, сортировка по физической позиции, per-frame RescaleSlope/Intercept, MONOCHROME1. Enhanced CT требует точных позиций всех кадров из functional groups.
- Совпадающие позиции, дубликаты SOP, смешанная/неравномерная геометрия отклоняются с объяснением. Файловые номера не используются для выдумывания позиций. Из нескольких серий выбирается самая большая корректная объёмная серия.
- Декодируется один кадр за раз. Удерживается один исходный сжатый объект/parsed dataset; многокадровый объект переиспользуется. В рабочий поток передаётся владение копией одного декодированного среза. Полная дополнительная float-копия объёма не создаётся.
- Массивы срезов и реконструкция находятся в Web Worker. Устаревшие реконструкции отменяются; закрытие исследования завершает worker и освобождает его память.
- Бюджет исходных пикселей: 20% доступного `navigator.deviceMemory`, минимум 256 MiB, максимум 1 GiB; если оценка браузером не предоставлена — 768 MiB. Этот лимит не является гарантией отсутствия OOM: остаются браузер, декодер и служебные буферы.
- Первые срезы загружаются от середины наружу; точный уже загруженный срез доступен до завершения серии. Неполученные значения прозрачны, вместо имитации изображения.
- Размер выходного Canvas ограничен 768 пикселями по ширине, для толстого слоя — 384; исходные пиксели и физические размеры не меняются. На слабом CPU толстый слой и повороты могут считаться дольше.
- Загрузка S3 после отмены может завершить один уже начатый запрос: текущий сервис не принимает AbortSignal. Новые запросы не запускаются.

## Проверка

- Общая регрессия ORBITAL: 54 набора, 377 тестов пройдено, один прежний тест пропущен. Дополнительно новый набор ввода CPU: 2 теста пройдено (включён в общий runner для следующих запусков).
- Проверены геометрия и физические размеры, обратное преобразование координат после масштаба/смещения, Enhanced CT, отрицательные/обlique направления, рескейл, частичная загрузка, DICOM LINEAR и MONOCHROME1, mean/MIP, отмена, бюджет памяти и освобождение parsed dataset.
- Production webpack сборка завершилась успешно; три существующих предупреждения о размере/сборке.
- В браузере тестовый локальный сервер принудительно возвращал `null` для любых WebGL-контекстов до старта приложения: автоматический CPU-путь открыл реальный сжатый пример 450 срезов и построил панораму. Масштаб, перемещение, синхронизация и раскрытие проверены визуально.
- Стресс-пример 800 × 800 × 750, 16 бит (около 916 MiB исходных пикселей) загрузился целиком, три плоскости видны. Это синтетический фантом без челюсти: отказ автопоиска зубной дуги ожидаем.
- Без отключения WebGL тот же build открыл обычный GPU-просмотрщик на малом синтетическом примере.
- Проверки проведены на локальном компьютере. Реальная скорость и покрытие конкретных проблемных компьютеров врачей требуют пилотной проверки.

## Файлы

- `platform/app/src/utils/startupRendering.ts`, `App.tsx`: выбор пути до GPU-инициализации.
- `platform/app/src/components/CpuViewer/`: UI, загрузка, геометрия, Canvas, worker и тесты.
- `ManualPanorama/RasterView.tsx`: необязательная инверсия MONOCHROME1, по умолчанию выключена; остальные потребители сохраняют прежнее поведение.
- `.scripts/test-orbital.cjs`: новые тесты включены в общую регрессию.

Для публикации требуется полная новая папка `platform/app/dist` с CPU chunk, CSS и worker/codec chunk; одного основного bundle недостаточно. Runtime-конфигурацию S3/CRM сохранять с сервера. Старые хешированные файлы сохранять для уже открытых вкладок.

# Совместимость графики ORBITAL 3D

## До открытия исследования

`platform/app/src/utils/volumeRenderingSupport.ts` проверяет настоящий контекст
WebGL 2, необходимые методы 3D-текстур, лимит размера и выделение минимальной
текстуры. Проверка выполняется до `appInit` и CRM resolve/загрузки исследования.
Проверочный контекст освобождается; повторного создания контекста при каждом
рендере React больше нет.

Без WebGL 2 показывается явное сообщение, что на этом компьютере исследование
открыть не получится, и инструкция по проверке аппаратного ускорения, браузера
и драйвера. Наличие API с неработающим выделением текстуры описывается отдельно.
Режим CPU без WebGL 2 в эту доработку не входит.

## Автоматическое облегчение

`adaptiveVolumeTexture.ts` оборачивает только контекст скалярной текстуры
конкретного объёма. При успешном выделении сохраняется существующий путь.
Существующая оптимизация больших signed Int16 объёмов также сохраняется.

При ошибке выделения текстуры выполняются ограниченные повторные попытки с
бюджетом 256, 128 и 64 МиБ. Перед повтором заменяется GPU handle текстуры.
Уменьшается только число отображаемых отсчётов по Z; выбранные исходные кадры
отображаются в соответствующие центры GPU-текселей. CPU-воксели, dimensions,
spacing, origin, direction, координаты измерений и камеры не меняются.

Некоторые драйверы сообщают о нехватке памяти только при загрузке пикселей.
Этот случай также запускает уменьшение бюджета: старая GPU-текстура
освобождается, уже закэшированные кадры загружаются повторно, без новых S3-запросов.

Если недоступна линейная фильтрация float-текстуры, используется поддерживаемая
выборка ближайшего вокселя и отображается соответствующая отметка. Это не
перекодирование исходного исследования.

Все MPR-окна показывают «Облегчённое отображение» и фактический шаг по Z либо
отсутствие сглаживания между вокселями. Снижение детализации отображения не
должно быть скрытым. Геометрическая система координат сохраняется, однако
визуальная детализация в облегчённом режиме действительно ниже.

При исчерпании попыток или потере активного графического контекста показывается
понятное сообщение вместо оставшихся чёрных окон. Уже использованный CRM-токен
не перезапускается автоматически: предлагается вернуться в личный кабинет.

## Ручное переключение

В шапке есть кнопка облегчённого режима. Настройка сохраняется локально для
браузера, без сведений об исследованиях. Переключение пересоздаёт только
GPU-ресурс, сохраняя текущие камеры, срезы и CPU-данные. Дополнительные GPU-фильтры
в ручном облегчённом режиме не выполняются. Возврат в автоматический режим
позволяет использовать обычную детализацию, если ресурсы доступны.

## Проверки

- Модульные проверки preflight, выделения/загрузки текстур, повторов и бюджета,
  отображения кадров, отсутствия float-интерполяции и сохранения CPU-геометрии.
- Браузер без WebGL 2: ясное сообщение, ни одного запроса CRM resolve.
- Ручное переключение: камеры и общий физический центр не меняются.
- Имитация ограничения памяти на синтетической серии 600×600×550:
  отказ 792 000 000 байт → успешное выделение 267 840 000 байт (186 отсчётов Z),
  все три MPR-окна показывают изображение уже при частичной загрузке.
- Имитация отказа всех бюджетов: явное сообщение, без JS-ошибок.

Эмуляция ограничений не подтверждает совместимость с каждым реальным драйвером.
Проверка на компьютерах врачей остаётся отдельной эксплуатационной проверкой.

## Android: наблюдение 12 ноября 2026

На подключённом realme RMX3830 (Android 15, около 4 ГБ RAM, Mali-G57,
Chrome 156.0.8078.79) пользователь сообщил: первые изображения появились,
затем загрузка завершилась сбоем. Открыта боевая веб-версия.

Системный журнал содержит остановку `com.android.chrome:privileged_process0`
12 ноября в 13:24:15 с причиной `LOW_MEMORY`, RSS около 1,2 ГБ. Событие
`CrGpuMain` подтверждает назначение привилегированного процесса. Аппаратная
графика включена. Это свидетельство нехватки памяти графического процесса;
сопоставление с конкретной вкладкой требует повторной проверки при открытом
экране телефона. Содержимое исследований и токены в журнал диагностики не включены.

На мобильных устройствах добавлен предварительный потолок скалярной текстуры
128 МиБ, действующий до первого выделения памяти, включая автоматический режим.
Иначе Android может уничтожить процесс до возврата WebGL-ошибки, и реактивное
уменьшение текстуры не успеет сработать. При необходимости остаётся попытка
64 МиБ. Мобильное устройство определяется по Android/iOS UA, включая iPad
с настольным UA и touch; обычные компьютеры с сенсорным экраном не ограничиваются.

Для 600×600×550 R32F первый запрос теперь составляет 133 920 000 байт
(93 отображаемых отсчёта Z), вместо 792 000 000 байт. Исходные CPU-данные
сохраняются. Это снижает расход GPU-памяти, но не гарантирует открытие любого
исследования: исходный объём, декодирование и панорама также требуют RAM.
Уменьшенная детализация обозначается существующей подписью во всех MPR-окнах.

### Проверка на подключённом телефоне

На этом же realme локальная сборка `app.bundle.b8b0af2185727f54a365.js`
успешно загрузила все 550 синтетических кадров 600×600 через настоящий Chrome
и его WebGL 2, без эмуляции отказов драйвера. Первая скалярная текстура сразу
600×600×93 R32F (133 920 000 байт), исходные dimensions остались 600×600×550.
Три MPR дают ненулевой диапазон яркостей; JS-ошибок нет. Повторная проверка
после загрузки: все семь контекстов живы, во всех трёх окнах есть отметка
об облегчённом отображении. Использованный JS heap около 462 МБ при лимите 1,07 ГБ.

Это проверка загрузки и MPR на синтетическом цилиндре, а не качества анатомии
или построения зубной дуги. Проблемный реальный снимок в новой сборке пока
не проверен. Отдельно прошли 26 модульных проверок
графики и браузерные проверки WebGL 2, ручного режима, сохранения камер и
обработки потери контекста на компьютере. Локальная сборка доступна на порту 3000;
для телефона настроено временное USB-перенаправление этого порта.

## Выкладка 12 ноября 2026

По запросу пользователя на `admin.orbital3d.ru/3dviewer/` включён релиз
`20261112T104830Z-ui-rendering-compatibility` с bundle
`app.bundle.b8b0af2185727f54a365.js`.

Переключена только ссылка на каталог статики. CRM, compressor и nginx не
перезапускались и не перезагружались; PID и время запуска служб сохранены.
Конфигурация nginx и `app-config.js` совпадают с предыдущими по SHA-256.
Все 288 прежних файлов с хешами в именах сохранены для открытых вкладок.
Резервная ссылка на прежний релиз:
`/var/www/orbital3d-viewer/backups/20261112T104830Z-ui-rendering-compatibility/3dviewer`.

Перед выкладкой прошёл полный набор: 48 suites, 352 tests passed, 1 skipped.
После переключения проверены HTTP-ответы и контрольные суммы HTML, runtime
config, build-info и bundle, заголовки изоляции и 404 отсутствующего asset.
На боевом адресе браузерные проверки подтвердили: отсутствие WebGL 2 даёт
понятный экран без CRM resolve, ручное облегчение сохраняет камеры и координаты,
потеря графического контекста даёт понятный экран без JS-ошибок.

Артефакт, журнал выкладки, проверки и команда отката находятся в
`tmp/production-viewer-20261112-compatibility/`. Скрипт `deploy_release.py rollback`
возвращает прежнюю ссылку без перезапуска служб; перед откатом проверяет,
что активен именно этот релиз.

### Последующая проверка реального исследования на Android

После выкладки пользователь самостоятельно открыл реальное исследование на
подключённом realme. Через CDP подтверждена именно новая боевая сборка.
Объём 900×900×750 полностью загрузился (`loaded=true`, `loading=false`),
все три MPR показывают изображение, все семь графических контекстов живы
при повторной проверке после завершения. Сработал мобильный бюджет:
82 отображаемых отсчёта Z при сохранении 750 исходных кадров, отметка
«Облегчённое отображение · шаг по Z 1,83 мм» присутствует во всех трёх окнах.

Автоматическая панорама этого исследования не построилась: интерфейс сообщает,
что костная дуга не распознана уверенно и предлагается ручное построение.
Это отдельное незакрытое замечание: результат проверки нельзя трактовать как
успешное выполнение всех функций на реальном исследовании. Персональные данные,
launch-токен, подписанные URL и изображения пациента в отчёт не включены.
Снимки состояния без персональных данных: `tmp/phone-real-study-*-state.json`.

# Проверка одного GPU-контекста

14 ноября 2026. Сборка опубликована на production по явному запросу пользователя. Повторная проверка ноутбука подтвердила один контекст, но потеря GPU-контекста сохраняется.

## Причина проверки

В предоставленном отчёте проблемного компьютера WebGL 2 аппаратно ускорен, Intel HD Graphics, драйвер 10.18.10.5100, около 3 ГБ RAM. Журнал показывает ошибку D3D11 `0x8007000E`, потерю контекста и падение GPU-процесса. В консоли приложения сохранено `compatibility`, затем `CONTEXT_LOST_WEBGL` и исключение VTK при `new Proxy(null, ...)`. Последнее — следствие отсутствующего контекста, а не свидетельство ошибки DICOM.

Код установленного Cornerstone 4.15.6 (`dist/esm/init.js`) задаёт `webGlContextCount: 7`. Конструктор WebGLContextPool создаёт семь offscreen multi-render window; объёмные viewports в ContextPoolRenderingEngine используют индекс 0, а распределение между остальными контекстами применяется к stack viewports.

Это дополнительная нагрузка независимо от размера объёма. Сокращение пула — проверяемая гипотеза, не доказательство устранения сбоя на старом Intel. Сохранённый флаг `compatibility` сам по себе не подтверждает успешное выделение уменьшенной текстуры.

## Изменение

- В ORBITAL (`standaloneMode: true`) и при сохранённом `compatibility` задаётся один контекст до `cs3DInit` и создания RenderingEngine. Остальные параметры конфигурации сохраняются.
- В других OHIF-профилях без этого режима остаётся исходный размер пула. Диагностический параметр `gpuContexts=1` может только уменьшить пул.
- Число окон, срезы, панорама, 3D-модель и инструменты не отключаются. Существующее облегчение текстуры продолжает работать отдельно и может снижать детализацию отображения.
- Настройка количества контекстов применяется при запуске. Переключение режима текстуры не пересоздаёт пул на лету. Для ORBITAL это не требуется: он изначально из одного контекста.
- В журнал выводятся читаемые JSON-строки `[orbital-rendering] GPU startup profile ...` и `[orbital-rendering] GPU context pool created {"contextCount":1}`. Вторая берёт фактический пул реализации, зарегистрированной в core, а не поле публичной обёртки RenderingEngine.
- При потере контекста убрана вводящая в заблуждение общая подсказка о включении ускорения; показываются сообщение о сбое графики и подробная причина.

## CPU-эксперимент исключён

По прямому указанию пользователя исходники, тесты, описание и снимки интеграции перенесены в `experiments/cpu-viewer-2026-11-14/`. Это архив вне исходников приложения и корней тестов. В App нет CPU-импорта, worker, автоматического перехода или обработчика `render=cpu`. Эксперимент не должен возвращаться без нового запроса пользователя.

## Проверка

- Общая регрессия: 51 набор, 366 тестов пройдено, один прежний тест пропущен. CPU-наборы исключены; добавлены четыре сценария выбора GPU-профиля.
- Конечная production-сборка успешно проверена в локальном браузере на реальном сжатом примере 450 срезов: три плоскости, панорама, переключение на 3D-череп и облегчение текстуры работают. В журнале зафиксирован фактический `contextCount:1`. Файл доказательства: `tmp/gpu-single-preview/rendering-log.json`.
- При тестовом принудительном отключении WebGL и сохранённом `render=cpu` отображается сообщение об отсутствии WebGL 2, CPU-интерфейс не запускается.
- Сборка webpack завершена успешно с тремя существующими предупреждениями; CPU-код отсутствует в активных исходниках и итоговых JS-файлах.
- Для вывода о проблемном компьютере необходим повторный прогон именно на нём. Успех на рабочей машине не подтверждает совместимость с его драйвером.

## Повторная проверка на ноутбуке

1. Открыть новую сборку из карточки пациента; прежнюю вкладку с упавшим процессом закрыть.
2. В консоли подтвердить `[orbital-rendering] GPU context pool created {"contextCount":1}`. Строка `using GPU rendering` ожидаема и не означает отключённое облегчение.
3. Сначала открыть небольшой снимок, затем проблемный. Сохранённый `compatibility` оставляем.
4. При новом сбое сохранить консоль и новый GPU report; не объявлять проблему исправленной только по флагу в localStorage.

## Результат на проблемном ноутбуке и следующий тест

Новый предоставленный журнал содержит `webGlContextCount:1`, `reason:"compatibility"`, `preference:"compatibility"` и фактический `contextCount:1`, затем `CONTEXT_LOST_WEBGL`. Заголовки JPEG2000 до этого читаются успешно. Сокращение пула не устранило сбой; точная причина потери контекста пока не установлена. Нельзя повторно объяснять его только старой сборкой или невключённым аппаратным ускорением.

Добавлена отдельная страница `platform/app/public/gpu-check.html`, опубликованная по адресу `https://admin.orbital3d.ru/3dviewer/gpu-check.html`. Она использует один контекст, проверяет чтение пикселя и 3D-текстуры R8/R16F/R32F, при наличии расширения — R16_SNORM, с nearest/linear. Размеры 32³ и 256×256×64, максимальная текстура 16 МиБ; текстуры удаляются последовательно. Это проверка небольших операций драйвера, не имитация полного потребления памяти просмотрщиком. Контекст намеренно не теряется через WEBGL_lose_context.

Страница не читает снимки, cookies или токены и не отправляет отчёт по сети (`connect-src 'none'`). Отчёт, включая последний этап, сохраняется локально; пользователь может скопировать или скачать его. При отсутствии EXT_texture_norm16 или float linear соответствующий сценарий явно пропускается.

Локально на AMD/D3D11 прошли 17 проверок без console error/warn; скачивание отчёта через кнопку проверено. Это не доказывает успех на Intel. Результат: `tmp/production-viewer-gpu-single/gpu-check-local-report.json`.

Опубликован только этот HTML (SHA-256 `d302fea3b4082601f38fd1e2ec3d03896c71d5ae660a3211ec938f7dc6aa205c`), без пересборки или изменения главного приложения. До и после совпадают хеши index/config/build-info/main bundle/nginx config, указатель релиза, PID и времена старта трёх служб. Отчёт выкладки: `tmp/production-viewer-gpu-single/gpu-check-deployment.json`. CPU-архив не используется.

### Отчёт пользователя с Intel HD Graphics

Файл `D:/orbital-gpu-check-2026-11-14T15-14-05-805Z.txt`: status `completed`, все 17 сценариев `ok`, включая R16_SNORM/R16F/R32F nearest и linear. Renderer — ANGLE Intel HD Graphics 0x0F31 D3D11; MAX_3D_TEXTURE_SIZE 2048. Создание WebGL2, малые выделения и выборки из 3D-текстур до 16 МиБ работают на проблемном устройстве. Это исключает полное отсутствие этих возможностей в данном прогоне, но не доказывает устойчивость полного движка или больших выделений.

Текущий compatibility ограничивает только scalar texture до 256 МиБ; остальные ресурсы движка и CPU-декодирование в этот бюджет не входят. Поэтому прохождение проверки 16 МиБ не противоречит потере контекста в приложении. Следующий эксперимент должен фиксировать реальные размеры, internalFormat, бюджет и этап выделения/загрузки до потери контекста и проверять существенно меньший предварительный бюджет. Падение под общей нагрузкой или ошибка конкретной операции движка остаются гипотезами; тест сам по себе не различает их. Новых изменений основного production-приложения после получения отчёта не выполнено.

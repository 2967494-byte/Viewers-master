# Автоматический профиль GPU — 14.11.2026

## Основание

Пользователь подтвердил на проблемном ноутбуке Intel HD 0x0f31: после устранения скрытого рендера черепа в профиле 64 МиБ работают срезы, панорама и явное включение 3D; небольшое замедление приемлемо. Это подтверждение одного компьютера, а не универсальная гарантия совместимости.

Задача: выбирать рабочий GPU-профиль без посещения gpu-check.html. Эксперимент CPU/Canvas остаётся исключённым из приложения.

## Выбор до загрузки исследования

Существующий preflight WebGL 2 проверяет минимальную текстуру 1×1×1. На том же контексте читаются доступные сведения об адаптере; дополнительного контекста, стресс-теста и крупных пробных выделений памяти нет. App инициализирует политику до appInit / Cornerstone.

| Условие | Бюджет текстуры объёма |
| --- | --- |
| SwiftShader / llvmpipe / известный программный WebGL-адаптер | 64 МиБ |
| Intel HD 0x0f31, HD 2000/2500/3000/4000, старое имя HD Graphics без номера | 64 МиБ |
| Телефон/планшет, браузер сообщает RAM ≤4 ГиБ | 64 МиБ |
| Телефон/планшет, RAM больше или неизвестна | 128 МиБ |
| Компьютер, RAM ≤2 ГиБ | 64 МиБ |
| Компьютер, RAM >2 и ≤4 ГиБ | 128 МиБ |
| Остальные, в том числе скрытое имя GPU без признаков нехватки памяти | Прежние ограничения просмотрщика |

Это эвристики, не измерение свободной видеопамяти. `deviceMemory` приблизителен, может отсутствовать; имя адаптера может быть скрыто политиками приватности. Современные UHD/Iris/HD 5000+ не объявляются старыми по наличию слова Intel. Отсутствие WebGL 2 по-прежнему сопровождается понятным отказом; программный WebGL здесь тоже использует GPU-путь библиотеки, это не наш архивный CPU/Canvas-просмотрщик.

64/128/256 МиБ — лимит одной scalar-текстуры, не общий расход RAM/VRAM браузера. При необходимости уменьшается число отображаемых Z-сэмплов. Исходные CPU-данные и пространственная геометрия сохраняются; подпись в окнах предупреждает о снижении детализации. Существующие ограничения мобильного устройства и очень больших объёмов продолжают действовать.

## Запоминание сбоя

При действительном context loss используемого движка запоминается следующий более осторожный бюджет 256→128→64 МиБ. При успешном восстановлении после GL_OUT_OF_MEMORY сохраняется бюджет восстановления. Намеренное закрытие движка игнорируется.

Ключ `orbital:gpu-recovery:v1` в localStorage содержит только локальную привязку к renderer/RAM/mobile/лимиту текстуры, бюджет и время. Срок 30 дней, несовпадение адаптера и некорректная запись игнорируются. Повторная запись не повышает ранее сниженный бюджет. Заблокированное хранилище не мешает работе. Эти сведения никуда не отправляются. Это не серверная настройка врача: разные компьютеры получают свои профили.

Новый бюджет применяется при следующей инициализации автоматического профиля. Потерянный контекст не пытаемся бесконечно перезапускать; страница предлагает заново открыть исследование. Аварийное завершение всего процесса браузера без события context loss не гарантирует запись подсказки.

## Ручное управление

Кнопка графики теперь открывает меню: «Автоматически» (с бюджетом, если ограничен), «Щадящий · 64 МиБ», прежний «Облегчённый · 256 МиБ», «Максимальная детализация». Ручная настройка сохраняется в существующем ключе предпочтения. Максимальная детализация обходит автоматическую эвристику, но не физические ограничения устройства и реакцию на ошибки GL.

Старое явно выбранное предпочтение `compatibility` не сбрасывается. Диагностический флаг 64 МиБ имеет приоритет и остаётся отдельным инструментом с журналом. Для проверки нового автомата на диагностическом ноутбуке: отключить тестовый флаг в gpu-check.html, открыть исследование заново, выбрать «Автоматически». При старом Intel в меню будет 64 МиБ уже без диагностического журнала.

В ограниченных профилях движок использует один GL-контекст с запуска. Для ORBITAL standalone это уже действующее поведение. Guard скрытого черепа сохраняется для всех режимов.

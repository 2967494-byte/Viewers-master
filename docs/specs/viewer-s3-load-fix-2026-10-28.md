# S3: исправления загрузки и прогресса (локальный код)

Дата: 28 октября 2026. Основание: `viewer-s3-load-status-2026-10-28.md`.

## Статус

Изменения внесены и проверены локально. На VPS не опубликованы. Доступный туннель
`http://127.0.0.1:18080/build-info.json` по-прежнему сообщает релиз
`20261028T201217Z-7d37627`. Ключи и реальные исследования для автоматических тестов
не использовались. CRM, DNS, S3 bucket и Uploader не изменялись.

## Подтверждённые ошибки кода

1. `orbitalS3ImageLoader` возвращал декодированное изображение с приватным
   `dicomfile:` imageId вместо запрошенного `orbitals3:`. События Cornerstone не
   совпадали с ожидаемыми ID индикатора. Теперь внешний ID сохраняется; внутренний
   используется только для декодирования. Для multiframe отделяется `&frame=N`,
   чтобы он не попадал в S3 object key; один файл скачивается один раз для его кадров.
2. На fast path сырые DICOM JSON-теги передавались в `addInstance` вместе с
   полями `url`/`_url`. При натурализации dcmjs трактовал строки пути как теги и
   превращал их в null. Теперь натурализуются только HEX-теги, URL присоединяется
   после преобразования. Поддержаны уже натурализованные объекты, относительные
   пути, полные object keys и прежние imageId-схемы. Проверяются три обязательных UID.
3. Строковые Rows/Columns/SamplesPerPixel и поля разрядности мешали строгим
   числовым сравнениям OHIF при проверке возможности MPR. Теперь эти поля
   приводятся к числам. Это воспроизвелось в браузерном тесте с JSON от dcmjs.
4. Поиск индекса перебирал папки последовательно, без явно заданного дедлайна,
   а любые ошибки скрывались как «индекса нет». Теперь выбранная папка и корень
   `appt_…` проверяются параллельно, максимум два запроса за раз. Проигравший запрос
   отменяется. Поиск не поднимается выше найденного корня appointment; максимум
   пять уровней сохранён. Таймаут отсутствия ответа/прогресса — 20 секунд,
   настраивается через `s3.metadataTimeoutMs`.
5. Только 404/NoSuchKey/NotFound разрешают продолжение поиска и fallback-индексацию.
   CORS/403/сетевая ошибка/битый JSON не запускают молча сканирование сотен файлов.
6. Completion volume вызывается также после ошибок кадров. Раньше индикатор мог
   засчитать все imageIds как загруженные. Теперь считает реальные изображения
   и кадры с FULL_RESOLUTION, показывает ошибки и снимает их после успешной догрузки.

Эти дефекты воспроизведены тестами. Они не доказывают, что именно они дали все
две минуты/420 КБ/с в конкретном серверном испытании: для этого нужен повторный
замер того же исследования после публикации исправлений.

## Поведение после исправления

- Начальный статус через React: поиск индекса, полученные МБ, число подготовленных
  срезов, переход в исследование. Убран точечный DOM-прогресс S3 на Local.
- После перехода индикатор в viewer считает срезы открытых серий, обновляется
  во время загрузки volume, показывает `процент · загружено/всего` и ошибки.
  Серии, не показанные ни в одном viewport, не увеличивают знаменатель.
- Центральный исходный срез самой большой CT/MR-серии выбранного исследования
  начинает загружаться до фоновой очереди. Изображения не заменяются искусственными.
- Существующая стратегия `nth` продолжает постепенно заполнять MPR. Полная
  автопанорама по-прежнему формируется после загрузки volume, а не по неполным данным.
- Ограничение SDK действует на передачу объектов целиком, включая чтение тела,
  а не только на получение HTTP-заголовков. Standalone: восемь реальных SDK GET
  одновременно максимум; Cornerstone interaction/thumbnail/prefetch = 8/2/6.
  Другие профили не переписывались.
- Из S3-формы убран предзаполненный путь конкретного пациента.
- Диагностика `[orbital-s3] metadata index ready` выводит байты, число инстансов и
  время получения; `metadata prepared` — время подготовки. Секреты не выводятся.

## Проверки

Unit-тесты: S3FileService (7), s3MetadataIndex (6), orbitalS3ImageLoader (2),
useS3Loader (3), LoadingProgressBar (4): **22 проверки**.

Браузерная интеграция: `tmp/check-s3-browser.cjs`, Chrome, собранный standalone,
локальная имитация SDK S3 и 24 синтетических DICOM-файла 128×128. Индекс —
стандартный HEX DICOM JSON в appointment root; запрос индекса в Data/ намеренно
зависает на пять секунд. Индекс найден без ожидания этого запроса. Каждый DICOM
запрошен один раз, Range/fallback-индексации нет, максимум шесть параллельных
пиксельных запросов в данном сценарии, промежуточный прогресс есть, ошибок JS нет.
Полный тест от кнопки загрузки до 100% — около 4,4 с. **Это результат локальных
искусственных данных, не оценка скорости Yandex S3 или настоящего КЛКТ.**
Отчёт: `tmp/s3-load-browser-report.json`.

Webpack standalone production-профиль с `QUICK_BUILD=true` успешно скомпилирован
и использован для интеграционного теста. Эта проверочная сборка без минификации
не является пакетом для публикации; перед релизом нужна обычная production-сборка
с `QUICK_BUILD=false` и совпадающим PUBLIC_URL. Предупреждения сборки — размеры
ассетов. Перед сборкой S3 access/secret env были очищены.

## Приёмка следующего релиза на том же исследовании

1. Собрать и опубликовать отдельный релиз по существующей Stage-1 инструкции,
   сохранить текущий релиз для отката. Проверить releaseId и Ctrl+F5.
2. Открыть тот же prefix. Должен сработать fast path; не должно быть ListObjects
   и Range-запросов к каждому DICOM для индексации.
3. Записать размер и время получения `ohif_metadata.json`, время подготовки,
   время первого полезного кадра, время полной серии и её размер.
4. Сверить число успешных GET, число срезов и движение прогресса; проверить
   запрет «100%» при сетевой ошибке и работу повторной загрузки.
5. Проверить реальные MPR, панораму, геометрию и инструменты на разрешённой копии.

При прямой передаче браузер → S3 пиксели не проходят через VPS. Настройки BBR/wmem
VPS не ускоряют этот участок. При реальном суммарном канале 420 КБ/с объём 200 МБ
потребует примерно восемь минут только на передачу. Метаданные, очередь и UI можно
исправить на клиенте; полное время большого volume потребует отдельно проверить
канал и объём, а затем при необходимости доставку/сжатие на стороне хранилища.

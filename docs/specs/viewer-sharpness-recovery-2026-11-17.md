# Защита от ошибок резкости

Статус: локальная правка, на сервер не выложена.

Поступил отчёт: при максимальной резкости пропали три MPR-изображения,
панорама осталась. Браузер Edge 157, ANGLE Intel HD Graphics D3D11.
В лёгкой диагностике нет ошибок загрузки или декодирования. Оценка текстуры
объёма 255,4 МиБ не включает буферы постобработки. Это не подтверждение
нехватки видеопамяти или конкретной ошибки драйвера. Исходный сбой на этом
оборудовании локально не воспроизведён.

Изменения:

- Коэффициенты фиксированного 5×5 фильтра обновляются в существующем массиве.
  VTK больше не получает `setKernel` при каждом движении бегунка: этот вызов
  меняет время модификации прохода и вызывает лишнюю пересборку экранного VBO.
- Обёртка прохода проверяет полноту нового framebuffer и ошибку WebGL после
  первого применения/изменения коэффициентов. Проверка `getError` не идёт
  при каждой прокрутке срезов.
- Привязки framebuffer (включая учёт VTK), viewport и scissor восстанавливаются
  после фильтра. При исключении или ошибке выполняется обычный forward pass,
  если графический контекст ещё доступен.
- Через microtask вне текущего прохода резкость обнуляется сразу во всех
  окнах. Повторное включение блокируется до перезагрузки страницы. Отложенное
  изменение бегунка отменяется; панель автоматически показывает сообщение.
- Потерянный контекст не запускает дальнейшие команды отрисовки фильтра.
  Восстановление потерянного контекста остаётся за существующей обработкой
  ошибок просмотрщика; эта защита не гарантирует восстановление драйвера.

Проверки: тесты исключения шейдера, неполного framebuffer, ошибки WebGL,
потери контекста, восстановления состояния, отсутствия повторных попыток,
общего сброса и отмены отложенного ввода. Реальный компьютер пользователя
нужен для подтверждения устранения исходного сбоя. Чёрный результат без
ошибок WebGL автоматически этой проверкой не определяется.

Локальная проверка завершена: 17/17 целевых тестов; production-сборка
`app.bundle.04fab11aa497f77d68af.js` успешно собрана (три прежних предупреждения
о размере). На реальном локальном исследовании проверены переключения
0 → 3 → 0 → 3 и прокрутка среза при 3×: все три изображения видимы,
новых ошибок в консоли не появилось. Снимок проверки:
`tmp/viewer-ux-quality/sharpness-recovery-3x.png`.

## Уточнение: несколько нажатий на пустой фон

Пользователь уточнил последовательность: усиление резкости, затем нажатия
на пустые области разных окон. В локальной сборке повторены нажатия на
фон коронального, сагиттального и аксиального окон. Общая точка перемещается
к границе объёма; два среза показывают почти только воздух. После установки
резкости в 0 эти срезы остаются почти пустыми. Выбор зуба на панораме возвращает
изображения во все три окна без перезагрузки. Это воспроизведение похожего
симптома из-за навигации, а не доказательство причины исходного случая на Intel.
Дополнительная защита фильтра не исправляет выбор краевого среза.

Если вводить ограничение навигации, различать фон вне геометрии объёма
и чёрные пиксели внутри снимка: воздух внутри снимка остаётся допустимой
областью выбора. Изменения такой навигации в этой правке не сделаны.

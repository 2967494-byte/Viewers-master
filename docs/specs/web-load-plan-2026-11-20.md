# Локальная оптимизация веб-просмотрщика: пункты 1–4

Дата: 20.11.2026. Изменения только в исходниках и отдельной локальной веб-сборке.
Боевой сайт и выданные установщики Windows не изменены.

## Реализовано

1. **Череп по запросу.** Для стандартного `mpr-3d` создание actor и применение его свойств отложены. Автопанорама получает идентификатор общего объёма без actor. Подготовка начинается при показе черепа или открытии редактора; ждёт загрузки всех слоёв и фоновых расчётов. Скрытый череп не отрисовывается. После первого показа actor сохраняется до выхода из исследования, чтобы сохранить камеру и не создавать его при каждом переключении.
2. **Освобождение источников.** Проверена ранее добавленная очистка parsed DICOM и ссылок загрузчика после декодирования поддержанных однофреймовых volume-изображений. Пиксели и метаданные срезов остаются. Stack и multiframe сохраняют прежний жизненный цикл. Нет уменьшения разрешения.
3. **Выход и смена исследования.** Очистка отменяет очереди и активные S3-запросы через AbortSignal, останавливает дальнейшие шаги устаревшего декодирования, отменяет подготовку черепа и расчёты панорамы/редактора, очищает их результаты, движок и кэш. Поздние callbacks свойств проверяют актуальность viewport и назначения серии. Отмена одного кадра не прерывает скачивание, которым пользуется другой кадр.
4. **Ограничение параллельной работы.** Полный конвейер скачивание/разбор/декодирование ограничен двумя задачами при сообщаемой памяти до 4 ГБ либо не более четырёх логических процессоров, иначе четырьмя. Автопанорама начинается после загрузки слоёв. Фоновые расчёты панорамы, раскадровки редактора и подготовка черепа идут через общую очередь по одному; отображение и навигация MPR этой очередью не блокируются. Отменённые ожидающие задачи удаляются.

Обе сборки в этой паре уже включают освобождение источников из пункта 2.
Замеры не доказывают ускорение на 42%: прогоны последовательные, кэш ОС и состояние GPU различаются; время не включает окончание построения автопанорамы. Существенное снижение общей памяти этим сравнением **не подтверждено**. Working set GPU-процесса не равен занятой видеопамяти. Принудительный GC используется только тестом.

Ранее отдельное сравнение пункта 2 описано в `web-source-memory-2026-11-20.md`: большой эффект на несжатых источниках, более скромный на обычной сжатой веб-серии. Не следует переносить экономию несжатых файлов на все исследования.

## Ограничения

- Общая текстура объёма нужна срезам и сохраняется. Отложенный череп не убирает её из памяти.
- Сбой общего WebGL-контекста по-прежнему способен затронуть все окна. Изоляция actor не является изоляцией графического контекста.
- Уже исполняемый декодер без cancelFn не прерывается посреди машинной инструкции: завершается ограниченное число активных задач, результат отменённой загрузки не используется и освобождается; новые задачи не запускаются.
- При локальной ошибке создания actor выводится сообщение в окне черепа; это не превращается в отклонение загрузки MPR. Потеря всего контекста обрабатывается общим механизмом восстановления.
- Старый компьютер и конкретные проблемные Intel ещё требуют проверки пользователем.

## Локальный запуск

`Запустить локальный веб-просмотрщик.cmd` запускает локальный сервер и открывает обычный браузер.
Текущая информация о сервере: `tmp/local-web-load-plan-20261120/server.json`.
Используются скачанные сжатые оригиналы, не предварительно распакованные desktop-файлы.
Приложения Windows служат только источником локальных тестовых данных и средой автоматического графического теста; их установщики не пересобирались.
